## P1：优先修复

### 1. 连续增量分析丢失中间轮次新增 K 线

位置：[prompt_assembler.py:1150](../pa_agent/ai/prompt_assembler.py#L1150)、[prompt_assembler.py:1215](../pa_agent/ai/prompt_assembler.py#L1215)。

`build_incremental_stage1()` 只取上一轮第一条 user 消息，然后重建固定四条消息。若上一轮本身就是增量分析，它最后一条包含新增棒的 user 消息被丢弃。完整分析 → 新增 A → 再新增 B 后，第二次增量包含最初全表和 B，缺少仍在当前窗口中的 A 的 OHLCV。原始全表的 K1 编号也未随窗口平移。默认阶段二 chain 继续继承该上下文。

**证据：**使用真实 `PromptAssembler` 和 45 根初始棒；A 的成交量设为 `7777777`，B 为 `8888888`。A 在首次增量请求中存在，第二次请求中完全消失，但第二次 frame 仍包含 A；B 存在，初始 user 全表逐字未变。

**建议：**保留完整、正确排序的增量消息历史，或在继续前重建当前全表。以至少两次连续增量的行为测试验证每根当前窗口棒均有正确数据与编号。

### 2. 改复权或历史价格修订后仍复用旧价格表

位置：[analysis_prep_worker.py:74](../pa_agent/gui/analysis_prep_worker.py#L74)、[analysis_history.py:108](../pa_agent/records/analysis_history.py#L108)。

历史记录仅按 symbol/timeframe 查找，增量判定只比时间戳，不检查重叠 OHLC。修改支持的 `kline_adjust`（qfq/hfq/none）并重新启动后，同一时间戳可对应完全不同价格，却得到 `new_count=0`，被默认增量阈值接受。请求继续保留旧全表，新增棒表为空。同代码、同周期切换数据源，以及历史行情修订也可能触发。

**证据：**将当前 frame 全部 OHLC 翻倍、时间戳不变，`compute_incremental_bar_delta()` 仍返回 0；真实增量请求包含旧 K1 完整行，不包含翻倍后的 K1 完整行。prep 路径没有其他价格一致性检查。

**建议：**比较重叠历史数据及来源/复权上下文；发生变化时采用完整分析。普通字段和数据比较足以解决，不需要新增 hash 或冻结机制。

### 3. 周/月线在每日收盘后仍被提前纳入 AI 快照

位置：[bar_close_wait.py:199](../pa_agent/data/bar_close_wait.py#L199)。

数据源的周/月线 forming 判断虽然已修复，`is_bar_still_forming()` 仍把 `1w/1M` 转成 `1d` 检查。周三 15:00 后，日线判定已结束，函数直接返回 False，后续周/月实际结束时间没有机会参与判断。快照构建由此把未完成周/月线重新标成已收盘 K1。

**证据：**同时固定 `now_ms` 和本机时钟为 2026-11-04 周三 18:00（上海时间）。周线、月线源判断均为 forming=True，快照判断均为 False；真实 `build_analysis_frame()` 接纳未完成头棒为 K1。

**建议：**将真实周期传给共享 forming 判断，并补“源返回 → 收盘判定 → AI 快照”的周/月边界测试。仅测试源侧函数不足以覆盖此问题。

### 4. 追问取消等待超时后，销毁窗口仍会导致 Qt 崩溃

位置：[ai_stream_window.py:607](../pa_agent/gui/ai_stream_window.py#L607)、[ai_stream_window.py:645](../pa_agent/gui/ai_stream_window.py#L645)、[main_window.py:4632](../pa_agent/gui/main_window.py#L4632)。

`shutdown_chat_worker()` 等待最多 5000ms，超时仅写日志。运行中的 `_ChatWorker` 仍以面板为父对象，随后关闭和对象销毁继续进行；保留 Python 引用不能阻止 Qt 父子对象级联销毁。客户端在收到流式 chunk 时才检查取消，网络停顿超过五秒足以让线程未退出。

**证据：**独立子进程中让 session 阻塞 30 秒，实际等待 5000ms 后 `running=True`、`parent_is_panel=True`；销毁面板后进程异常退出 `3221226505 / 0xC0000409`。

**建议：**超时后解除面板对运行线程的所有权，交由生命周期更长的持有者回收，或延迟销毁到线程实际结束；不要强制 terminate 线程。用独立进程测试超时分支。

### 5. 明确输入上证指数，被静默换成平安银行

位置：[ashare_common.py:38](../pa_agent/data/ashare_common.py#L38)、[baostock_source.py:65](../pa_agent/data/baostock_source.py#L65)。

`normalize_ashare_symbol()` 仅对白名单指数保留 sh/sz 前缀，白名单不含 `000001`。Baostock 自己预设列表中的 `sh000001` 被规范化为 `000001`，随后按股票查询 `sz.000001`。用户选择上证指数，实际获取的是平安银行。`sh000688` 也存在同类交易所信息丢失。

**证据：**真实 `BaostockSource.subscribe('sh000001', '1d')` 后，`_query_code(source.symbol)` 返回 `sz.000001`。

**建议：**保留并正确解释用户明确指定的交易所，区分裸码默认值与显式前缀；对预置品种逐一验证最终 API 查询代码。

### 6. Tushare 裸码反复触发切换，GUI 无法启动分析

位置：[tushare_source.py:251](../pa_agent/data/tushare_source.py#L251)、[base.py:129](../pa_agent/data/base.py#L129)、[main_window.py:3191](../pa_agent/gui/main_window.py#L3191)。

通过配置启用 Tushare（它当前不在默认数据源下拉列表中）后，`subscribe('600519', '1d')` 将订阅保存为 `600519.SH`，但没有覆写 `canonical_symbol()`，其结果仍为 `600519`。提交路径永远认为品种发生变化，执行重新订阅并 return。Baostock/EastMoney 接受的部分带前缀输入也存在同族不一致。

**证据：**使用真实 Tushare subscribe/unsubscribe、真实 MainWindow 提交/切换方法，仅替换 GUI 副作用和持久化。连续三次提交均通过可提交检查，却产生三次重新订阅、零次分析启动；下拉文本始终为 `600519`，订阅始终为 `600519.SH`。

**建议：**各源的 canonical 方法与 subscribe 使用同一规范化函数，扩展既有 WeStock 提交回归用例覆盖其他数据源。

### 7. Tushare 把普通 0009xx 股票当指数请求

位置：[tushare_source.py:103](../pa_agent/data/tushare_source.py#L103)。

`is_tushare_index()` 用 `digits.startswith('0009')` 判指数，误伤 `000938.SZ`、`000963.SZ`、`000977.SZ` 等股票。真实日线请求因此使用 `asset='I'`、`adj=None`，无法得到对应股票历史。

**证据：**替换外部 `tushare.pro_bar`，执行真实订阅及 `_fetch_daily(120)`，上述股票均发出 `asset='I'` 请求，股票应为 `asset='E'`。

**建议：**使用明确的指数代码和交易所识别规则，避免将整个股票前缀视作指数。

## P2：后续修复

### 8. 东财实时日线成交量仍比历史放大 100 倍

位置：[eastmoney_source.py:407](../pa_agent/data/eastmoney_source.py#L407)、[ashare_common.py:179](../pa_agent/data/ashare_common.py#L179)。

历史 Baostock 路径已统一为手，但实时 quote 覆盖仍设置 `volume_lots=True`，把 quote 的手数乘以 100 转股；补当日日线的路径也使用相同转换。

**证据：**真实 `EastMoneySource.latest_snapshot(2)`，外部历史边界返回当日和历史各 500 手，quote 同样为 500 手，最终成交量为 `[50000, 500]`，closed 标志 `[False, True]`，确认历史确实走已修复的 Baostock 路由。

影响主要是实时图表虚假放量。正常 closed-only AI 快照会排除该 forming bar，本报告不将它描述为已污染正常 AI 输入。建议统一 quote 覆盖和历史的单位，并测试最终 source 输出。

### 9. ISO 日期不兼容，反手冷却过期仍被触发

位置：[decision_continuity.py:109](../pa_agent/ai/decision_continuity.py#L109)、[two_stage.py:201](../pa_agent/orchestrator/two_stage.py#L201)。

记录用 `isoformat()` 写出 T 分隔日期，冷却计算只接受空格分隔，解析失败便返回默认 1 根。在旧方案未失效的情况下，超过三根冷却后的同结构反手仍会被程序改成不下单。

**证据：**5m 周期间隔一小时，ISO 日期得到 1 根并拒绝反手；只将日期分隔符改为空格，同一时刻得到 12 根并允许。建议使用兼容 ISO 的解析，并以实际保存记录测试读取链路。

### 10. 关闭声音弹窗同时禁用交易记录及外部通知

位置：[main_window.py:3761](../pa_agent/gui/main_window.py#L3761)、[main_window.py:4516](../pa_agent/gui/main_window.py#L4516)。

交易 CSV/图表和飞书、PushPlus 调度依赖 `_maybe_alert_order_opportunity()` 返回 True，而该方法在 `alert_on_order_opportunity=False` 时立即返回 False。设置说明仅承诺控制声音、弹窗和页面跳转。

**证据：**有效订单机会下关闭本地提醒，`_has_order_opportunity=True`，但真实完成回调不调用 `_spawn_post_order_followup`。建议独立按订单机会调度记录/通知，再按偏好播放本地提醒。

### 11. 切换品种后，旧追问完成会重新开放旧会话

位置：[main_window.py:2271](../pa_agent/gui/main_window.py#L2271)、[ai_stream_window.py:695](../pa_agent/gui/ai_stream_window.py#L695)。

品种切换清空 MainWindow 的 `_free_chat_session` 并禁用输入，但面板仍持有旧 `_session`，旧 worker 也继续运行。旧回复完成后无条件重新启用输入框；按钮仍禁用，但回车绑定可直接发送。

**证据：**阻塞旧追问 → 禁用输入模拟切换 → 放行旧回复，得到输入框启用、按钮禁用、旧会话仍保留；回车后旧 session 实际收到第二次请求。用户可能在新图表中继续使用旧品种分析上下文。

建议切换时取消并解除面板旧会话，完成回调先确认仍属于当前会话再修改输入状态。

### 12. 宣称支持 macOS，但无法保存 API Key，环境变量提示也不可用

位置：[settings.py:473](../pa_agent/config/settings.py#L473)、[ai_model_settings_dialog.py:156](../pa_agent/gui/ai_model_settings_dialog.py#L156)。

非 Windows 平台 `_dpapi_protect()` 返回 None，保存非空 Key 必定抛 RuntimeError，设置对话框没有处理该失败。错误提示建议环境变量，但普通 provider 设置加载和客户端没有读取 OPENAI_API_KEY/DEEPSEEK_API_KEY，客户端还显式传入空字符串 Key。

**证据：**模拟 darwin 后向临时目录保存非空伪造 Key，必定 RuntimeError；同时设置两个常见 Key 环境变量后 `provider_api_key_configured(load_settings(...))` 仍为 False。

建议实现明确的环境变量配置路径或 macOS 安全凭据存储，并处理保存异常。不要通过恢复明文落盘来绕开现有保护。

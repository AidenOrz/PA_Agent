# 网络代理问题与解决办法

> 适用场景：中国大陆网络环境下使用 PA Agent 的 TradingView / AkShare 等数据源时，遇到的网络连接问题及解决方案。
>
> 本文档整理了实际踩过的坑与修复方案，按「问题现象 → 根因 → 解决办法」的结构编写。

## 1. 概述：为什么需要代理

| 数据源 | 服务器 | 国内直连 | 是否需要代理 |
| ------ | ------ | -------- | ------------ |
| TradingView | `data.tradingview.com` | ❌ TCP 超时 | **必须** |
| AkShare（东方财富） | `push2his.eastmoney.com` 等 | ✅ 可直连 | **不要**（被代理拦截反而失败） |
| MT5 | 本地终端 | — | 不需要 |

- **TradingView** 的服务器在国内网络下直连不通（TCP 层超时），必须通过本地代理（Clash / V2Ray 等）访问。
- **AkShare / 东方财富** 是国内站点，直连即可。若本机开启了代理并设置了 `HTTP_PROXY` 环境变量，请求反而会被代理转发导致失败（`ProxyError`）。
- **MT5** 读取的是本地 MetaTrader 5 终端数据，不走网络。

## 3. TradingView 数据源

### 3.1 问题现象

```log
WARNING  pa_agent.data.tradingview: TradingView fetch failed: timed out
WARNING  pa_agent.data.tradingview_connectivity: TradingView connectivity probe failed: TradingView 连接超时（OANDA / XAUUSD）...
```

状态栏反复提示连接超时，图表无法刷新。

### 3.2 根因

tvDatafeed 底层通过 **WebSocket**（`websocket.create_connection`）连接
`wss://data.tradingview.com/socket.io/websocket`，而 **WebSocket 库不会自动读取
`HTTP_PROXY` / `HTTPS_PROXY` 环境变量**。因此即使本机有代理，tvDatafeed 也是直连
TradingView，在国内网络下必然超时。

### 3.3 解决办法（已内置，无需手动操作）

程序已在 `pa_agent/data/tradingview.py` 中内置了 **WebSocket 代理注入**：

- 连接时自动检测本机代理（详见 [第 6 节](#6-代理检测机制说明)）；
- 检测到代理后，monkey-patch `tvDatafeed.main.create_connection`，为 WebSocket 连接
  注入 `http_proxy_host` / `http_proxy_port` 参数；
- 断开数据源时自动还原，不影响其他模块。

**用户需要做的**：确保代理软件（Clash / V2Ray 等）已启动。

### 3.4 常见问题排查

| 现象 | 原因 | 处理 |
| ---- | ---- | ---- |
| 日志出现 `未检测到可用代理，TradingView 将直连（可能超时）` | 代理软件未启动 / 未设置系统代理 / 端口不在常见列表 | 启动代理软件；或在系统设置中开启系统代理 |
| 日志出现 `Patched tvDatafeed WebSocket to use proxy ... (from env/registry/port-probe)` | 正常，代理已生效 | — |
| 自动探测 AAPL 等美股极慢（数十秒） | 使用的旧版本（缺美股探测分支） | 更新代码，`equity_tv_auto_probe_plan` 已支持美股 |
| 手动选交易所 OANDA + 品种 AAPL 失败 | OANDA 没有 AAPL | 交易所选「自动」或 NASDAQ |
| 日志出现 `'NoneType' object is not callable` | 使用了旧版 patch 代码 | 更新代码 |

## 4. AkShare（东方财富）数据源

### 4.1 问题现象

```log
WARNING  pa_agent.data.akshare_source: AkShare 主源失败 (601138): HTTPSConnectionPool(
  host='push2his.eastmoney.com', port=443): Max retries exceeded ...
  Caused by ProxyError('Unable to connect to proxy', ...)
```

或：

```log
('Connection aborted.', RemoteDisconnected('Remote end closed connection without response'))
```

### 4.2 根因

两种典型原因：

1. **代理拦截**：本机设置了 `HTTP_PROXY` 环境变量（或系统代理），AkShare 请求东方财富
   时被转发到代理，而代理无法访问国内站点（或代理规则把国内域名也转发了）→ `ProxyError`。
2. **东方财富反爬**：`push2his.eastmoney.com` 有 IP 级频率限制。短时间内多次请求
   （或重试过密）会触发风控，服务器直接断开连接 → `RemoteDisconnected`，封锁持续数分钟到一小时。

### 4.3 解决办法

1. **让东方财富请求绕过代理**：
   - 在 `NO_PROXY` 环境变量中加入 `.eastmoney.com,.eastmoney.net`；
   - 或直接关闭系统代理 / 在代理软件中为国内域名配置直连规则（Clash 默认分流通常已直连国内）。

2. **避免触发反爬**：
   - `pa_agent/data/akshare_source.py` 内置了请求节流（默认 0.9s 间隔）；
   - 若仍触发封锁，可增大 `_AK_MIN_INTERVAL_S`（如 3~5 秒）并减少
     `_call_with_retries` 的重试次数（如 4 → 2）；
   - 被封锁后需等待冷却（约 30 分钟 ~ 1 小时），期间不要反复尝试。

3. **启用 Baostock 备用源**（可选）：
   - 设置环境变量 `PA_AGENT_BAOSTOCK_FALLBACK=1`，AkShare 主源失败时自动切换
     Baostock（不走东方财富，不受其反爬影响）。

### 4.4 常见问题排查

| 现象 | 原因 | 处理 |
| ---- | ---- | ---- |
| `ProxyError('Unable to connect to proxy')` | 请求走了代理但代理不通 | 将东方财富域名加入 NO_PROXY；或关闭代理直连 |
| `RemoteDisconnected`（所有请求突然全部失败） | IP 被东方财富风控封锁 | 停止请求，等待冷却后再试 |
| 第一次请求成功、之后全失败 | 测试期间请求过密触发风控 | 冷却后重试；调大节流间隔 |

## 5. MT5 数据源

MT5 数据源读取本机 MetaTrader 5 终端，**不涉及网络代理**。

| 现象 | 处理 |
| ---- | ---- |
| `MT5 未连接` | 打开 MT5 终端并登录账户 |
| 品种红色警告 | 品种名需与 MT5「市场报价」完全一致（含后缀，如 `XAUUSDm`） |

## 6. 代理检测机制说明

程序对 TradingView 数据源采用 **三级代理检测**（`TradingViewSource._detect_proxy`），
按顺序找到第一个可用的代理即使用：

| 优先级 | 来源 | 说明 |
| ------ | ---- | ---- |
| 1 | 环境变量 | `HTTPS_PROXY` / `HTTP_PROXY`（及小写形式） |
| 2 | Windows 系统代理 | 读取注册表 `HKCU\...\Internet Settings` 的 `ProxyEnable` + `ProxyServer`（Clash/V2Ray 开启系统代理时写入） |
| 3 | 常见本地端口 | 探测 `7890 / 10808 / 1080 / 10809 / 7897 / 8888 / 8080` |

> **为什么需要第 2 级？**
> 从命令行启动程序时，环境变量通常存在；但**双击（GUI）启动时，进程环境里没有
> `HTTP_PROXY`** —— 代理软件只写系统代理注册表。因此必须读取注册表才能覆盖
> GUI 启动场景。

**没有代理时**：日志输出 `未检测到可用代理，TradingView 将直连（可能超时）`，
程序不报错退出，只是 TradingView 拉不到数据。

## 7. 常见故障速查表

| 症状 | 最快定位 | 处理 |
| ---- | -------- | ---- |
| TradingView 一直 `timed out` | 看日志是否有「未检测到可用代理」 | 启动代理软件 / 检查系统代理 |
| TradingView 偶发超时后恢复 | 代理软件重启/节点切换 | 无需处理，自动重试 |
| AAPL 等美股拉取极慢（83s） | 日志中探测尝试 OANDA 等外汇交易所 | 更新代码（美股探测分支） |
| AkShare 报 `ProxyError` | 检查是否有代理环境变量 | 东方财富域名加入 NO_PROXY |
| AkShare 报 `RemoteDisconnected` | 是否刚做过多次请求 | 等待冷却，调大节流间隔 |
| 切换数据源卡住 | RefreshLoop 未退出 | 等待或重启程序 |

## 8. 日志排查指南

日志位置：程序运行目录下的 `logs/` 文件夹（具体以程序输出为准）。

排查网络问题时，按以下顺序检查日志关键词：

1. `未检测到可用代理` → 代理软件未启动（TradingView 场景）
2. `Patched tvDatafeed WebSocket to use proxy ... (from env|registry|port-probe)` → 代理已生效
3. `TradingView fetch failed: timed out`（无 1、2 时）→ 代理未生效或代理本身不通
4. `AkShare 主源失败` / `RemoteDisconnected` → 东方财富风控或代理拦截
5. `MT5 未连接` → MT5 终端未启动

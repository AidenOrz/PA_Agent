# PA Agent 缺陷修复计划

> 制定日期：2026-08-04
> 当前状态：源码修复完成，聚焦验证完成，宽回归存在既有环境/契约缺口
> 范围：基于 `交接文档.md` 与当前工作树复核结果；本文件只记录本轮修复计划和验收边界。

## 1. 目标与边界

目标是修复会导致数据错位、记录丢失、非法 AI 输出被接受、请求重复或后台线程失控的缺陷，并为每个修复补充最小回归测试。

本轮不做以下事情：

- 不修改 `config/settings.json`、`records/pending/`、`trade_records/`、`logs/` 或用户生成的研究资料。
- 不回写或重算已有交易记录；新文件命名和新写入从修复版本开始生效，历史文件继续兼容读取。
- 不重构无直接验收价值的业务逻辑，不把 lint 风格问题混入功能修复。
- 不进行真实 API 调用、真实交易或 provider/key 轮换；外部服务只使用 mock/本地探针测试。

## 2. 分阶段范围

### 阶段 A：数据与持久化完整性（P1，已完成）

写入边界：`records/`、`config/paths.py`、相关测试。

- 修复记录文件名 `%m`/`%M` 混淆，并保持旧记录可查找。
- 为 pending JSON 和交易 CSV 提供原子写入；CSV 追加/迁移写入增加进程内锁，避免并发丢行。
- 清洗 symbol、timeframe、record_id 的文件名组件，阻止路径穿越和分隔符注入。
- 将 `trade_records` 统一锚定 `PROJECT_ROOT`。
- 明确配置损坏、保存中断和密钥持久化的恢复策略；不读取或输出真实密钥。

验收：并发写入行数保持完整；写入中断不会留下可解析的半截正式文件；恶意路径组件不会越出目标目录；同一秒不同记录不覆盖。

### 阶段 B：校验与两阶段恢复（P1，已完成）

写入边界：`ai/`、`orchestrator/`、相关测试。

- 让“不下单 + 非空价格”在归一化前后都保留为校验错误，不能先清空字段再返回 `Ok`。
- 修复 `inside`/`outside`/`trend_*` 结构一致性检查，并让 strict/lenient 参数真正影响行为。
- 捕获校验重试 API 异常，统一累积 usage 并保存带阶段信息的 partial。
- 取消流式调用时保存已有的阶段消息、原始响应和取消原因；禁止向 `save_partial` 传 `None`。
- 降级只在当前分析调用内生效，排除 4xx 业务/认证错误，不永久改写用户 provider 配置。
- `stream_options` 仅在明确的参数不支持错误时重试，避免不确定状态下重复请求。

验收：非法输出触发 `Stage1Failed/Stage2Failed`；取消、网络错误、重试网络错误均产生可解析 partial；4xx 不触发网络降级；一次已提交但客户端超时的请求不会无条件二次提交。

### 阶段 C：周期与数据源语义（P1/P2，已完成）

写入边界：`data/`、相关测试。

- 为 `1M` 增加大小写和日历月语义，按月末/下月月初判断收盘。
- 指数周线/月线向东方财富接口传递 `klt=102/103`，并验证返回周期与请求周期一致。
- AkShare、Tushare、东方财富统一读取复权设置；不引入静默的 qfq 默认覆盖用户选择。
- TradingView 探针 timeout 后不在退出线程池上下文中同步等待无限期后台任务。

验收：`1M` 不再映射为分钟；指数请求参数与周期一致；复权配置分别覆盖 qfq/hfq/none；timeout 测试在设定时间内返回。

### 阶段 D：GUI 生命周期与展示防御（P1/P2，已完成）

写入边界：`gui/`、相关测试。

- 统一分析、快照、准备 worker 的取消、失效、等待和 zombie 回收协议。
- 线程未结束时保留引用，不直接置空或让 QThread 被垃圾回收。
- 展示层对字符串/区间价格做防御性解析，不能因格式异常中断整次展示。
- 将 GUI 线程中的阻塞 sleep 改为异步定时器。

验收：取消和关闭窗口不会出现 `QThread: Destroyed while thread is still running`；异常价格只显示占位或错误状态；主线程不被固定 sleep 阻塞。

## 3. 协作与写入所有权

- 主 Agent：维护本文件、处理阶段 C/D、复核所有子代理改动、运行最终测试。
- 子代理 1（`gpt-5.6-luna`, `max`）：只修改阶段 A 文件和对应测试。
- 子代理 2（`gpt-5.6-luna`, `max`）：只修改阶段 B 文件和对应测试。
- 阶段 C/D 不与子代理写入重叠；共享的 `tests/conftest.py`、配置和文档由主 Agent 维护。
- 任何代理不得修改运行配置、业务记录、日志或清理用户文件。

## 4. 验证顺序

1. 先运行修改模块的最小单元/属性/集成测试。
2. 再运行不依赖 live API、GUI 外部 fixture 的 unit/property 子集。
3. 对 worker、月线和指数周期增加 mock 边界测试。
4. 最后运行 `ruff`/编译检查并记录环境缺口；不把缺少 `pytest-qt` 或过期测试契约误报为功能回归。

## 5. 停止条件与恢复点

若原子写入、取消协议或 provider 降级的根因无法在当前边界内验证，停止扩大修改，保留最后通过的测试结果，并在 `docs/HANDOFF.md` 或本文件追加具体阻碍。每个阶段完成后先复核 diff 和测试，再进入下一阶段。
